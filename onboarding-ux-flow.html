Onboarding UX Flow — Proposal (v2, compressed)

A walkable mockup of the four-screen onboarding sequence from PRD Section D — Welcome, a merged "Your household" screen (required counts up top, optional detail + the reused Principles component open by default below), "Add a few recent meals," and a fully automatic Completion. Use the controls under the phone to step through; "Your household" and "Add a few recent meals" demonstrate the live preview panel updating as data is entered.

Screen 1 of 4

Screen 1 — Welcome

First thing a new user sees after verifying their email or completing Google sign-in. Purely orienting — no data entry yet.

1

Value pitch is concrete, not generic

Leads with what the product does and previews that answers directly improve tonight's dinner suggestion, rather than a vague "welcome!" screen.

2

Three-stat pitch row

Quick visual reinforcement of the "more data = better plan" idea before asking for any effort. Purely illustrative copy here, tune wording later.

3

Skip for now is visible but de-emphasized

Present from the very first screen, per the PRD's "skippable but nudged" decision — never hidden, never the primary action.PRD: Section D, P0

Screen 2 — Your household

This is the screen that changed most from the earlier draft: what used to be two separate steps (Household basics, then Principles) is now one screen with a required tier and an open-by-default optional tier — not a hard step split, and not a hidden "Advanced" toggle either.

1

Required tier: adults & kids, top of screen

Steppers, not a text field — every generation prompt reads adults/kids directly, so this is the one thing onboarding actually blocks on. Try tapping "Save & continue" with adults at 0 — it's blocked inline, matching the PRD's acceptance criterion.PRD: Section D, P0

2

Optional tier: open by default, not collapsed

Quick fields for allergies, likes, dislikes, pantry staples, and this week's use-up items — plus the existing 5-checkbox-plus-free-text Principles component from Settings, embedded here as-is (same underlying storage, no redesign). All of it is visible immediately; none of it blocks continuing.

3

Live preview panel reacts on save

Try it: set adults/kids, fill in anything below (or don't), and tap Save & continue. The preview card swaps to a dinner that reflects what was entered, with a brief highlight pulse and an "Updated ✨" tag — the concrete proof-of-value moment from the PRD, not just a completeness meter.

Screen 3 — Add a few recent meals

Directly reuses the existing "Add meal history" form (description, optional recipe link + Fetch recipe, Yes/Mostly/Not really feedback, optional note) — no new fields introduced.

1

Soft target, lowered to "a couple"

The earlier draft asked for 3–5; this version asks for "a couple" — proportionate to this being the last screen standing between the user and their generated plan. Still a suggestion, not a minimum enforced before continuing.

2

Added meals show as a running list

Each saved meal appears as a small chip above the form, so the user sees visible progress without needing a separate summary screen. Zero meals is a valid way to reach Finish.

3

Preview keeps reacting

The same live preview panel from Screen 2 persists here and updates again as meals are added — reinforcing the same feedback loop with a second, different kind of input.

Screen 4 — Completion

No user input happens on this screen — everything here runs automatically the moment the user arrives, confirming onboarding is done and handing off into an app that's already tailored, not generic.

1

Board of advisors seeded silently

The 5 standard personas are inserted here with no screen of their own. The 2 is_customizable personas seed with their defaults — customizing them is deferred entirely to Settings, not surfaced anywhere in onboarding, to keep this to two data-entry screens.PRD: Section D, P0

2

First week generated synchronously, then marked complete

Reuses propose-week's core logic with the same force-override bypass the app already has, so a brand-new household doesn't wait for Saturday's cron. Only once seeding and generation both succeed does this screen show its confirmation and set onboarding_completed_at.

3

Single CTA into "This week"

Tapping through triggers the full loadHouseholdData() reload per the PRD's state-reload requirement, so the first real screen they see reflects a clean fresh load — not leftover pre-onboarding state.

4

If they skipped earlier, this screen is simply never shown

A user who tapped "Skip for now" at any point lands directly in the app with a generic plan and no advisors seeded; the existing in-app nudge banner becomes their path back in, and re-entering onboarding resumes at Screen 3 since the required fields on Screen 2 are the only thing that gates resumption.
